# Работа с FFmpeg

Это набор приёмов, не универсальная цепочка «улучшения». Выполняй из папки ролика.
Ниже `input.wav`, `prepared.wav`, `master.wav`, `delivery.wav` — примеры путей;
подставляй реальные файлы. Каталог `renders/audio/` создавай по необходимости.
Все выходы должны отличаться от исходников; `-n` запрещает перезапись.
При нескольких аудиопотоках сначала выбери нужный: `0:a:0` означает первый,
а не автоматически правильный язык/дорожку.

## Проверка доступности

```sh
ffmpeg -version
ffprobe -version
ffmpeg -hide_banner -filters
ffmpeg -hide_banner -encoders
ffmpeg -hide_banner -h filter=acompressor
ffmpeg -hide_banner -h filter=loudnorm
```

База анализа: `ebur128`, `astats`, `silencedetect`; обработки: `volume`,
`acompressor`, `afade`, `aresample`, `loudnorm`. Остальные фильтры проверяй по
необходимости. Нужны `pcm_f32le` для мастера и выбранный доставочный кодек
(например `aac` для MP4). Фильтры и опции сверяй с локальным `-h filter=...`.

## Анализ без изменения записи

```sh
ffprobe -v error -show_streams -show_format -of json input.wav
ffmpeg -nostdin -hide_banner -v error -xerror -i input.wav -map 0:a:0 -f null -
ffmpeg -nostdin -hide_banner -i input.wav -map 0:a:0 -af ebur128=peak=true -f null -
ffmpeg -nostdin -hide_banner -i input.wav -map 0:a:0 -af astats=metadata=0:reset=0 -f null -
ffmpeg -nostdin -hide_banner -i input.wav -map 0:a:0 -af silencedetect=noise=-40dB:d=0.15 -f null -
```

Сохраняй stderr команд в разные логи внутри проекта. `ebur128` показывает
momentary M и short-term S во времени, итоговые I/LRA и true peak; начальные окна
ещё не заполнены. Значения тишины/невалидных окон не усредняй как громкость речи.
Порог `silencedetect` здесь иллюстративный: подбирай по шуму, проверяй тихие согласные.
Silence detection не распознаёт слова и не заменяет VAD/alignment. Для подозрительного
места анализируй отдельно и контекст соседних реплик; сохраняй смещение его таймкода.

Для очень короткой/немой записи показатели могут быть недостоверны или `-inf`:
не подставляй их в gain/нормализацию. Сначала установи наличие полезного сигнала.
Не объявляй файл хорошим только по успешному декодированию или числу пиков.

## Проба динамической обработки

Для уже измеренной отдельной реплики можно изменить постоянный уровень,
например уменьшить на 3 dB, сохранив отдельную float-копию:

```sh
ffmpeg -nostdin -n -i input.wav -map 0:a:0 -af volume=-3dB -ar 48000 -c:a pcm_f32le leveled.wav
```

Число выбери по сравнению с соседними активными репликами, не по имени файла.
Это не меняет внутренние перепады. Не нормализуй каждую короткую фразу вслепую:
разная длина, паузы и речевые акценты влияют на измерение и восприятие.

Пример **только для пробы**, не рекомендуемый пресет любого голоса:

```sh
ffmpeg -nostdin -n -i input.wav -map 0:a:0 -af "acompressor=threshold=0.125:ratio=2:attack=15:release=150:makeup=1" -ar 48000 -c:a pcm_f32le prepared.wav
```

Здесь threshold — линейная амплитуда (0.125 ≈ −18 dBFS), attack/release — мс.
Слишком высокий порог не обработает проблему, слишком низкий подавит всю речь.
Настрой по входному уровню; не включай автоматическое makeup без контроля пиков.
Компрессор не заменяет согласование уровней разных файлов.

Для локальной огибающей можно использовать `volume` с `eval=frame`, выражения
с плавными участками или команды `asendcmd`. Не делай мгновенный скачок gain
внутри волны. Для `alimiter` проверь `level` (auto-level включён по умолчанию)
и `latency`: задержка может нарушить синхронизацию. True peak контролируй отдельно.
Для `dynaudnorm`/`speechnorm` сначала проверь предел усиления, реакцию на паузы,
задержку, длину выхода и pumping; не добавляй оба поверх компрессора без причины.

## Каналы до нормализации

Если договор доставки — dual-mono, подготовь его **до обоих проходов измерения**:

```sh
ffmpeg -nostdin -n -i master-mono.wav -map 0:a:0 -af "pan=stereo|c0=c0|c1=c0" -ar 48000 -c:a pcm_f32le master.wav
```

При одинаковом уровне в обоих каналах измеренный I обычно примерно на 3 LU выше
обычного mono-измерения. Это не новый клиппинг и не универсальный stereo gain.
Альтернатива для mono, предназначенного к воспроизведению как dual-mono:
осознанное `dual_mono=true` в измерении. Не сочетай эту компенсацию с повторной
ручной поправкой. Настоящую stereo-музыку не превращай в dual-mono.

## Двухпроходная нормализация мастера

Пример целей: I=−16 LUFS, TP=−1.5 dBTP, LRA=11. Это не стандарт OMR и не
гарантия комфорта: используй выбранные для проекта цели. Между проходами нельзя
менять файл, каналы, gain, паузы или фильтры перед `loudnorm`.

Первый проход только измеряет; JSON находится в stderr:

```sh
ffmpeg -nostdin -hide_banner -i master.wav -map 0:a:0 -af "loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json" -f null -
```

Не разбирай весь stderr как JSON: рядом есть диагностические строки, в том числе
после закрывающей скобки. Извлеки JSON-объект и проверь наличие ожидаемых полей.
`-n` защищает существующий выход, но код возврата при пропуске может зависеть от
версии FFmpeg: проверяй фактическое создание нового файла, а не только exit code.

Во второй проход перенеси **все** измерения первого: `input_i` → `measured_I`,
`input_lra` → `measured_LRA`, `input_tp` → `measured_TP`, `input_thresh` →
`measured_thresh`, `target_offset` → `offset`. Переменные ниже должны содержать
эти конечные числа, а не примерные значения или `-inf`:

```sh
ffmpeg -nostdin -n -i master.wav -map 0:a:0 -af "loudnorm=I=-16:TP=-1.5:LRA=11:measured_I=${INPUT_I}:measured_LRA=${INPUT_LRA}:measured_TP=${INPUT_TP}:measured_thresh=${INPUT_THRESH}:offset=${TARGET_OFFSET}:linear=true:print_format=json" -ar 48000 -c:a pcm_f32le delivery.wav
```

`linear=true` — запрос, не гарантия линейного режима. При невозможности достичь
целей без динамической обработки FFmpeg может перейти в dynamic; проверь
`normalization_type` в результате, не скрывай переход. `-ar 48000` явно задаёт
выходную частоту после возможного внутреннего oversampling. Измерь сохранённый
файл заново: предсказанные `output_*` не заменяют проверку артефакта.
Не пытайся одним LRA всей программы исправить короткое резкое слово.

## Кодирование и проверка доставки

При совпадающем таймлайне и подходящем lossless-мастере можно не перекодировать
видео. Пример выбирает только один видеопоток и новую аудиодорожку; если нужны
другие потоки/субтитры/метаданные, явно сохрани их отдельно:

```sh
ffmpeg -nostdin -n -i picture.mp4 -i delivery.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k -ar 48000 -movflags +faststart final.mp4
ffprobe -v error -show_streams -show_format -of json final.mp4
ffmpeg -nostdin -hide_banner -v error -xerror -i final.mp4 -map 0:a:0 -f null -
ffmpeg -nostdin -hide_banner -i final.mp4 -map 0:a:0 -af ebur128=peak=true -f null -
```

Не применяй `-shortest` для сокрытия расхождения длительностей. AAC может менять
пики, добавлять padding; сравни длительности потоков и полезную речь отдельно.
При превышении true peak измени мастер/запас и перекодируй **из мастера**, не из
предыдущего AAC. Проверь начало, конец, стыки и глобальную синхронизацию; проверка
корреляцией/импульсами не доказывает правильность произношения или границ слов.

Для A/B подготовь отдельные прослушиваемые копии одного фрагмента с сопоставимым
уровнем, сохраняя боевые файлы. Сравнивай не только «громче», но и скачки слов,
шум в паузах, шепелявость и утомительность. Запуск проигрывателя не доказывает,
что агент воспринимает аудио: при отсутствии аудиовосприятия слушает человек.
