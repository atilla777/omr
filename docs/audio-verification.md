# Проверка общего звукового процесса

Дата: 19 октября 2026. Объём: исходники `omr-audio`, подключение к производству
и ревью, сценарный договор тайминга, документация зависимостей и FFmpeg-рецепты.
Персональные ролики, TTS-сервис и глобальные настройки не изменялись.

## Что проверено

- Новый `omr-audio` обнаружен текущей OpenCode V2 `2.0.32` и реально загружен
  инструментом `skill`; ресурс `references/ffmpeg.md` доступен и прочитан.
  Отдельная команда не добавлялась, число команд остаётся восемь.
- Метаданные, ссылки и границы источников просмотрены: нет зависимости от
  Qwen/сервера, путей машины или установки TTS. `omr-render` явно подключает
  скил для звука; профиль render-ревью — в режиме анализа. Сценарий сохраняет
  прогноз и допустимые пределы адаптации, не запускает производство.
- На машине доступны Git `2.55.0`, Python `3.14.7`, Node `26.8.1`, npm `11.19.0`,
  uv `0.13.1`, Manim CE `0.22.0`, FFmpeg/FFprobe `n9.0.1`, mpv, fontconfig,
  latex и dvisvgm. Typst CLI в PATH отсутствует; это не доказывает отсутствие
  Python Typst-пути Manim. Его компиляция в этой проверке не выполнялась.
- Указанные в README и dependencies 33 уникальные HTTP-адреса (без `.git`
  clone-адреса) ответили HTTP 200. Это проверка доступности страниц, не проверка
  установки пакетов на всех ОС. Для FFmpeg, Manim и Remotion прочитаны официальные
  руководства. Manim-скил явно обозначен как сторонний, `manim-local` — машинный.
- Обнаружено, что `fc-match 'Noto Sans:style=SemiBold'` возвращает Regular.
  Поэтому инструкция требует реальные начертания, а не только наличие семейства;
  шрифты системы не менялись. Проверка шрифтов конкретного ролика остаётся
  обязанностью его производства.
- Найдены все базовые звуковые фильтры; команды реально выполнены на синтетике.
- Проверены 56 локальных Markdown-ссылок затронутой документации и ресурсов,
  метаданные скила, Python-синтаксис и `git diff --check`; ошибок нет.

## Повторяемая численная проверка

Из корня исходников, нужны Python 3, FFmpeg/FFprobe с `libx264` и `aac`:

```sh
python3 -m unittest discover -s tests -p 'test_audio_recipes.py' -v
```

Тест создаёт только временные файлы; для другой папки задайте `TMPDIR`. Локально
использован `/tmp/opencode`. Дополнительные пакеты Python, модели и сеть не нужны.

Все пять тестов прошли:

1. `ebur128=peak=true`, `astats`, `silencedetect` и полное декодирование.
2. Mono → dual-mono: увеличение измеренного I на **3.01 LU**.
3. Постоянный gain сохраняет контраст участков **20.00 dB**; пример компрессии
   уменьшает его до **15.40 dB**, сохраняя длину и нулевую тишину. Это результат
   для искусственного сигнала, не оптимальный пресет речи. Проверены неизменность
   исходника, конечные float-отсчёты и сохранность существующего выхода при `-n`.
4. Полная тишина даёт невалидную для нормализации громкость; её нельзя усиливать
   по формуле из `-inf`.
5. Предварительное согласование уровней участков → обработка → dual-mono → два
   прохода loudnorm → float-мастер → AAC в MP4 с копированием видео → повторное
   декодирование/измерение. Конечный файл: **−16.03 LUFS, −1.49 dBTP**, AAC stereo
   48 кГц; длительность аудио соответствует 12 с с допуском 0.1 с.
   Зафиксирован `normalization_type=dynamic`, несмотря на `linear=true`:
   руководство запрещает считать линейный режим гарантированным.

При первоначальном прогоне исправлены допущения теста: за JSON в stderr могут
идти другие сообщения; `-n` не обязан возвращать ненулевой код при сохранении
старого выхода. Также грубо невыравненные участки с паузой не попали точно в цель
одним loudnorm: тест теперь явно согласует уровни **до** мастеринга, как требует
скил, а не ослабляет проверку цели. Эти наблюдения учтены в руководстве.

## Границы подтверждённого

Проверка маршрутизации **чтением инструкций**, не новый живой прогон агентов:

| Запрос | Ожидаемое поведение |
|---|---|
| Выровнять уже записанные реплики | `omr-audio`, без TTS |
| Проверить звук готового ролика | `omr-review` + `omr-audio`, только анализ |
| Получить речь из текста | Не задача `omr-audio`; выбранный источник у производителя |
| Немой ролик / написать сценарий / арифметика | Сам по себе `omr-audio` не нужен |
| Нет FFmpeg / исходника | Точный блокер, без скрытой установки и заглушки |

Не проводились: новая сквозная установка в чистую область, автономное выполнение
агентом скила на речи, прослушивание, приёмка конкретного голоса, тестирование
на других ОС/сборках FFmpeg, новый рендер Remotion/Manim, проверка браузера и
всех зависимостей формул. Исходники скила и численные рецепты готовы; комфорт речи
и поведенческая надёжность на следующих проектах требуют отдельной проверки.
Текущий звук `ris-sdlc` не исправлялся. Публикация и commit не выполнялись.
