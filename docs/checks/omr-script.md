# Проверка `omr-script`

Дата: 16 октября 2026. Проверка задачи 5 на небольших условных входах через
новые процессы OpenCode 1.18.33 CLI. Исходники созданы после загрузки
`ris-port-op-author-skill` и `customize-opencode`. Пользовательский ролик
не создавался. Папки ниже явно выбраны как тестовые проекты внутри общего
Git-дерева, без собственного `.git`; входы и результаты сохранены на месте.

## Исходники и структурные проверки

- Скил: `.opencode/skills/omr-script/SKILL.md`; имя совпадает с папкой,
  описание содержит положительные и соседние случаи, укладывается в 1024 символа,
  лицензия MIT. Дополнительных ресурсов и обязательных скилов-зависимостей нет.
- Команда: `.opencode/commands/omr-script.md`, `description`, непустое тело
  с загрузкой скила и `$ARGUMENTS`; без закреплённых модели, агента или `subtask`.
  Локальное подключение выполнено размещением в штатных папках по поручению задачи.
- Из `docs/checks/omr-script/remotion/` `debug config` распознал шаблон,
  `debug skill` обнаружил ровно один `omr-script` с телом 8131 символ.
  Большой JSON получен через `script -q -c 'opencode debug skill' /dev/null`,
  разобран Python; `assert` проверили наличие и поля команды/скила.
- Просмотрены соответствие SPEC, границы этапа, отсутствие циклических зависимостей,
  условия загрузки технических скилов, переносимость путей, эквивалентные входы,
  выбор подпапки, правка существующего сценария, частичный результат и отказ записи.
  Это просмотр инструкций, не живой прогон каждой ветви.

Технические скилы нужны только при проверке конкретных возможностей движков;
обычный текстовый сценарий их не требует. В наблюдаемых прогонах был загружен
только `omr-script`; техническая реализация и доступность движков не проверялись.

## Реальный вызов команды в трёх режимах

В каждой из трёх папок запускалась команда:

```sh
opencode run --format json --command omr-script 'Техническая проверка задачи 5 на условном примере. Эта папка — выбранный проект. Прочитай requirements.md и content/index.md с материалами, создай пригодный к реализации script.md и перечитай его. Только сценарий, затем остановись. Не делегируй работу.'
```

| Режим | Сессия | Входы и неизменённый результат |
| --- | --- | --- |
| Remotion | `ses_ebbef21bdffekGkvYD5FyCW09K` | [требования](omr-script/remotion/requirements.md), [индекс](omr-script/remotion/content/index.md), [сценарий](omr-script/remotion/script.md) |
| Manim CE | `ses_ebbef21bbffepXIv3CEuAVplQg` | [требования](omr-script/manim/requirements.md), [индекс](omr-script/manim/content/index.md), [сценарий](omr-script/manim/script.md) |
| Гибрид | `ses_ebbef21bdffeKx342S7ln0cwGF` | [требования](omr-script/hybrid/requirements.md), [индекс](omr-script/hybrid/content/index.md), [сценарий](omr-script/hybrid/script.md) |

В каждом наблюдались `skill(omr-script)`, чтение входов, запись и перечитывание
`script.md`. Результаты независимо просмотрены по содержимому файлов/выводу чтения,
а не только по итоговому сообщению агента:

- **Remotion:** вымышленный кружок, три сцены 3/4/5 секунд, 90/120/150 кадров;
  перенесены все четыре реквизита, исключены незаданные адрес/цена/регистрация.
  Заданы шрифт-стек, размеры, координаты, кривая прозрачности, переходы внутри
  сцен, слои композиции, отсутствие аудио и внешних ресурсов. Десятичные секунды
  записаны с запятой; однозначные целочисленные кадры дублируют эти интервалы.
- **Manim:** четыре участка одной Scene по 3 секунды; пять сохраняемых точек,
  формула, координаты, `run_time`/удержания. Сумма действий — 12 секунд.
  Четыре точные короткие реплики привязаны к действиям, оценка 80–120 слов/мин
  отделена от измерения будущей записи. Есть задание на запись пользователя
  в `public/voice.wav`, паузы, параметры и сведение FFmpeg без добавления Remotion.
- **Гибрид:** Remotion 3 с + вставка Manim 6 с + Remotion 3 с; 90+180+90 кадров.
  У вставки определены содержание, координаты, начальный/конечный фон,
  1920×1080/30 FPS, непрозрачный H.264 без звука, пути будущего файла и копии
  в `public/`, отображение локальных кадров 0…179 на глобальные 90…269,
  масштаб 1:1, слои и контроль прямых стыков. Формулы/титры не дублируются.

Все три таймлайна непрерывны и дают 360 кадров при 30 FPS = 12 секунд;
переходы входят в длительность сцен. Границы и суммы дополнительно проверены
Python assert. Планируемые ресурсы не выданы за существующие. Текст/речь короткие,
есть удержания и паузы; фактическая читаемость и звучание на этом этапе не измеряются.
Факты не расширены: вымышленные реквизиты и непосредственный счёт точек заданы
тестировщиком. Поиск источников здесь не нужен и не проверяется.

Сессия `ses_ebbec9dd9ffe09DElcP6NCYKZa`. [Бриф](omr-script/mode-conflict/brief.md)
содержит согласованный Manim-only и новую обязательную директиву сборки Remotion,
требующую гибрида. Это намеренное противоречие, а не техническая невозможность
нарисовать две точки в Manim. Агент назвал конфликт, сохранил и перечитал
[частичный script.md](omr-script/mode-conflict/script.md) с явным блокером,
не назначил новый режим и спросил: согласовать гибрид или сохранить Manim-only
и отменить новую директиву. Требования не переписаны; полного договора гибрида
до ответа нет, результат не объявлен готовым. Ответ на уточнение не подавался.

## Эффекты и ограничения

- Во всех тестовых проектах только Markdown: три положительных получили по одному
  `script.md`, конфликтный — один частичный, недостаточный остался без изменений.
  Индексы и исходные требования/контент сохранены. Производственных папок,
  package-файлов, кода, медиа и вложенного Git нет.
- JSON-трассы трёх положительных запусков дополнительно разобраны: загружен
  `omr-script`, отсутствовали вызовы `bash` и `task`; записи затрагивали только
  сценарий (в Remotion после перечитывания исправлен подсчёт слов).
- Проверены 66 локальных Markdown-ссылок в 20 файлах, метаданные, тайминг
  и `git diff --check`.
  Идентификаторы сессий и неизменённые файлы выше — сохранённые свидетельства;
  полные машинные трассы остаются в локальном хранилище OpenCode, не в репозитории.
- Повторная точечная правка, запуск из корня с выбором/созданием подпапки,
  отсутствие отдельного индекса при штатных входах, отказ записи, недоступность
  технического скила, длинная речь и переходы с перекрытием проверены только
  просмотром инструкций. Готовая запись, TTS и реальные внешние медиаресурсы
  отдельными живыми примерами не проверялись. CLI-уточнения были текстовыми,
  без интерактивного `question`.
- Рендер, просмотр и прослушивание MP4 относятся к производству и не выполнялись.
  Следующий этап не запускался; задача 6 не начата. Commit/push не выполнялись.
  Новая команда доступна после выхода и перезапуска OpenCode; текущая сессия
  новые конфигурационные файлы автоматически не перечитывает.
