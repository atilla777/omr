# Проверка ведущего OMR и независимого ревью

Дата: 16 октября 2026. Изменение пакета, не создание пользовательского ролика.

## Реализовано

- `omr` и `/omr`: основной диалог, требования у ведущего, остальные этапы у
  субагентов, отдельный ревьюер, остановки и разрешения после этапов целиком.
- `omr-review` и `/omr-review`: общий метод, четыре профильных руководства,
  отчёты в `reviews/`, без исправления артефактов самим ревьюером.
- До двух кругов исправлений после первоначального ревью. Для возобновления
  короткая заметка с фазой, использованными кругами и разрешением продолжить.
- Все четыре скила этапов читают существующие отчёты. Самостоятельные вызовы
  не запускают ревью. Нет версий, хешей или реестра устаревания.
- README рекомендует `/omr` и содержит запрос и порядок установки для агента,
  включая перенос `references/`, сохранение пользовательских правил и перезапуск.

## Статическое независимое ревью

Другой `general`-субагент проверил изменения read-only
(`ses_ebaed70b0ffeQmMH9wh3rL3aAI`). Обнаружил два упущения:

1. Самостоятельная команда ревью могла проверять работу своего автора.
   Исправлено через `agent: general`, `subtask: true`.
2. При возобновлении мог теряться лимит кругов исправлений.
   Исправлено указанием хранить фазу и использованные круги в короткой заметке.

Повторное read-only ревью подтвердило устранение обоих замечаний в инструкциях.
Это проверка исходников, не свидетельство успешного полного конвейера.
Финальная проверка `git diff --check` прошла без замечаний.

## Обнаружение и наблюдаемый запуск

В локальном игнорируемом `projects/omr-coordinator-check/` подготовлены достаточные
требования условного четырёхсекундного немого приветствия и `workflow.md`:
требования созданы, первоначального ревью ещё нет, контент не разрешён.
Движки не устанавливались. Из подпапки новыми CLI-процессами проверены:

- `opencode debug config`: обе новые команды и четыре команды этапов обнаружены;
  у `omr-review` распознаны `agent: general` и `subtask: true`.
- `opencode debug skill` через псевдотерминал: обнаружены `omr` и `omr-review`
  с непустыми описаниями и путями к текущим исходникам.
- `opencode run --command omr 'Продолжи по workflow.md…'`: ведущий реально
  загрузил `omr`, прочитал требования и заметку, сохранил фазу и вызвал отдельного
  `general`-субагента для первоначального ревью требований.

**Блокер:** дочерняя задача `ses_ebaeaf9e3ffeM4yIsBeYx1Qst8` получила
`auto-reject external_directory` на предках рабочей папки (`/*`, `/home/*`,
`/home/aleksei/*`, `/home/aleksei/plums/*`). Ведущий получил ошибку делегирования,
сохранил её в `workflow.md` и запросил разрешение повторить запуск. Отчёт ревью
не создан; контент, код и видео не создавались. Запрет не обходился и разрешения
пользовательского окружения не менялись.

Таким образом подтверждены загрузка ведущего, восстановление заметки, попытка
делегирования и корректная остановка на блокере. Успешное завершение ревью и
переход к контрольной точке после него **не подтверждены**.

## Границы проверки

Не выполнены: успешный отдельный вызов `/omr-review`, прохождение нового полного
процесса до MP4, реальные два круга исправлений, возврат между этапами и отдельная
новая установка восьми компонентов по README. Выбор новых скилов на естественных
положительных, соседних и нерелевантных запросах проверен только чтением описаний,
не живой матрицей. Работа четырёх производственных этапов ранее проверена отдельно;
эти свидетельства не доказывают новую оркестрацию.

Для завершения проверки нужен разрешённый запуск дочерних задач с доступом к
проекту и его правилам; после этого — повтор учебного ревью и контрольной точки.
Сохранённая локальная учебная папка позволяет продолжить без пересоздания входов.
