## Реализация и команды

Все команды выполнены из `/tmp/opencode/omr-install-check/demo`.
Сцена: `src/manim/leap_year.py`, класс `LeapYearComparison`.
Мгновенные `add`/`remove` и два `wait(2, frozen_frame=True)`;
анимаций, перемещения камеры и дополнительных титров нет.
Размеры текста задаются в пикселях через масштаб камеры, центры и подгонка
ширины соответствуют сценарию. Жёлтый цвет задан только span числа `366`.

Предварительные проверки:

```bash
manim --renderer cairo --media_dir renders/draft-s01 --resolution 640,360 --fps 30 -s -n 0,0 src/manim/leap_year.py LeapYearComparison
manim --renderer cairo --media_dir renders/draft-s02 --resolution 640,360 --fps 30 -s src/manim/leap_year.py LeapYearComparison
manim --renderer cairo --media_dir renders/draft --resolution 640,360 --fps 15 --disable_caching src/manim/leap_year.py LeapYearComparison
ffmpeg -y -v error -i renders/draft/videos/leap_year/360p15/LeapYearComparison.mp4 -frames:v 1 renders/draft/first.png
```

Оба still-вызова фактически сохранили второй экран: `-n 0,0` в данном запуске
не дал ожидаемый первый экран. Это обнаружено при открытии PNG. Первый экран
проверен отдельно по `renders/draft/first.png`, извлечённому из чернового MP4.
Все эти PNG реально открыты инструментом `read`. Предупреждение о deprecated
`set_height` устранено заменой на присваивание `height`; итоговый рендер без него.

Повторный полный рендер и подготовка итогового файла:

```bash
manim --renderer cairo --media_dir renders/manim --resolution 640,360 --fps 30 --disable_caching src/manim/leap_year.py LeapYearComparison
ffmpeg -y -v error -i renders/manim/videos/leap_year/360p30/LeapYearComparison.mp4 -map 0:v:0 -c:v copy -an -movflags +faststart out/video.mp4
```

`out/` должен существовать (при первом запуске создан через `mkdir -p out`).
FFmpeg только перепаковывает видеопоток Manim, без повторного сжатия и без
`-shortest`. Промежуточный результат:
`renders/manim/videos/leap_year/360p30/LeapYearComparison.mp4`.

Проверка и извлечение реальных PNG:

```bash
/home/aleksei/.local/share/uv/tools/manim/bin/python src/manim/verify_video.py
ffprobe -v error -show_entries stream=codec_name,codec_type,width,height,pix_fmt,r_frame_rate,avg_frame_rate,nb_frames,duration -show_entries format=duration,size -of json out/video.mp4
```

`verify_video.py` использует имеющиеся NumPy и Pillow, вызывает
`ffprobe -v error -count_frames -show_streams -show_format -of json out/video.mp4`,
затем полностью декодирует видео командой:

```bash
ffmpeg -v error -xerror -i out/video.mp4 -map 0:v:0 -f rawvideo -pix_fmt rgb24 pipe:1
```

Из полученных RGB-кадров скрипт сохраняет PNG и контактный лист в
`renders/keyframes/`; это кадры **итогового MP4**, не отдельного still-рендера.
Метаданные сохранены в `renders/probe.json`, измерения — в `renders/checks.json`.

## Проверка кодирования и таймлайна

| Параметр | Фактический результат |
| --- | --- |
| Контейнер / кодек | MP4 / H.264 |
| Формат пикселей | yuv420p |
| Разрешение | 640 × 360 |
| FPS, nominal и average | 30/1 |
| Длительность видео и контейнера | 4.000000 с |
| Кадры, метаданные и полное декодирование | 120 |
| Потоки | Один видеопоток, аудио отсутствует |
| Размер | 22 367 байт |

Полное декодирование всех кадров прошло без ошибок. Единственная существенная
смена изображения — перед кадром **60**, то есть ровно в 2.000000 с.
Средняя абсолютная RGB-разница соседних кадров на склейке — 6.01853,
максимум внутри экранов — 0.003464 (шкала канала 0–255).
Порог обнаружения смены сцены в проверочном скрипте — 0.1.

**Ограничение точности:** текст и камера статичны, но lossy H.264 создаёт
малые межкадровые различия пикселей: 7 различных декодированных RGB-изображений
в первом блоке и 6 во втором. Побитовая идентичность 60 кадров каждого экрана
не достигнута; эти различия не интерпретируются как анимация. По просмотренным
PNG визуальных изменений внутри экранов нет. RGB-цвета на сглаженных краях
и после yuv420p также не обязаны точно совпадать с исходными hex-цветами.

## Фактический визуальный просмотр PNG

Открыты инструментом `read`:

- `renders/keyframes/contact-sheet.png`: кадры 0, 30, 58, 59, 60, 61, 90, 119;
- отдельно в конечном размере 640 × 360:
  `frame-000.png`, `frame-059.png`, `frame-060.png`, `frame-119.png`.

Результат просмотра:

- Кадры 0 и 59: только «Обычный год: 365 дней», белый текст на чёрном.
- Кадры 60 и 119: «Високосный год: 366 дней» и «+ 29 февраля»;
  только число `366` жёлтое. Обе строки полностью показаны с кадра 60.
- Кириллица читается, квадратов, пропусков символов, наложений, кавычек,
  добавочных титров и обрезания не обнаружено. Формул и внешних медиа нет.
- Пара 59/60 — прямая склейка; соседние 58/59 и 60/61 показывают удержания.
  Переход имеет нулевую длительность, поэтому внутреннего кадра перехода нет.
  Пустого кадра, смешивания экранов и затемнения не обнаружено.
- Последний кадр содержит весь второй экран, без заставки или fade-out.

Измеренные границы видимого текста (порог максимального RGB-канала >64,
правая и нижняя границы исключены):

| Кадры | x | y | Проверка полей |
| --- | --- | --- | --- |
| 0, 30, 58, 59 | [145, 495) | [166, 194) | Внутри 32 px, центр (320,180), высота 28 px |
| 60, 61, 90, 119, общий bbox двух строк | [120, 520) | [136, 222) | Внутри 32 px |

Сценарные центры второго экрана (320,150) и (320,210), размеры 28 и 24 px
заданы в исходнике; расположение и разделение строк подтверждены просмотром.
Небольшая разница в границах сглаженных растровых глифов относительно векторного
bbox возможна. Безопасные поля проверены программно на всех восьми PNG.

## Ограничения и сохранность

- Непрерывное воспроизведение видео и оценка в реальном времени не проводились:
  GUI/плееры запрещены тестом. Визуальный контроль выполнен только по реальным PNG;
  тайминг и отсутствие существенных изменений между ними — по декодированию
  всех 120 кадров. Побитовая статичность оговорена выше.
- Ролик немой; отсутствие аудиопотока проверено. Прослушивание не применимо.
- Первоначально DejaVu Sans не был доступен в Pango, `fc-match` возвращал
  Liberation Sans. Попытки поиска в `/usr/share`, `/usr/lib` и домашнем каталоге
  были отклонены разрешениями; в `/tmp/opencode` файл не найден.
  После явного обновления требований поиск прекращён; ограниченные каталоги
  не обходились. Дальнейшая работа использует согласованный Noto Sans.
- Диагностика редактора не разрешает импорты Manim/NumPy/Pillow из системного
  Python; реальное выполнение в указанном uv-окружении успешно, импорты и рендер
  проверены им. Отдельный системный Python не настраивался.
