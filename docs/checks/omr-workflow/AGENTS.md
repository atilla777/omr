# Пользовательские правила тестовой области

- Сохраняй файл `owner-notes.md` без изменений.
- В этой области примеры помечаются словом «УЧЕБНЫЙ».
- Не делегируй работу и не запускай подагентов.

## OMR: рабочая область и проекты роликов

- Поддерживаются Remotion, Manim Community Edition и гибрид. Режим согласуется
  с пользователем в требованиях.
- Каждый ролик находится в отдельной подпапке этой рабочей области без своего
  `.git`. Текущая подпапка определяет проект; из корня сначала выбери подпапку.
- Структура материалов: `requirements.md`, `content/index.md`, `content/<тема>.md`,
  `script.md`, `public/`, `src/remotion/`, `src/manim/`, `renders/`, `out/video.mp4`.
  Индекс контента обязателен. Папки создаются по необходимости.
- Этапы `/omr-requirements`, `/omr-content`, `/omr-script`, `/omr-render`
  запускаются вручную по поручению пользователя. Не запускай следующий или
  предыдущий этап автоматически и не обновляй зависимые результаты без поручения.
- Проверяй достаточность входов; существенные пробелы и противоречия уточняй.
  При отсутствии входов предложи соответствующую команду без её запуска.
  Достаточные эквивалентные материалы пользователя допустимы.
- Загружай профильные скилы через `skill` до соответствующей работы.
  Для Remotion используй `remotion-best-practices`, для Manim — вместе `manim`
  и `manim-local`, для гибрида — скилы обоих движков.
- Не устанавливай движки заранее. Remotion и его зафиксированные зависимости
  принадлежат конкретному Remotion- или гибридному проекту; не используй
  `node_modules` корня или соседнего ролика. Для чистого Manim не создавай Node-проект.
- Для Manim используй подходящее имеющееся окружение, описанное в `manim-local`;
  при особых зависимостях — отдельное окружение проекта. Не изменяй общее окружение
  без согласования. Отсутствующие скилы и инструменты явно обозначай.
- Команды установки, разработки и рендеринга выполняй из папки ролика.
  При редактировании сохраняй работу пользователя за пределами поручения.
- Проверяй сборку, параметры MP4, ключевые кадры, переходы и предусмотренный звук;
  различай кодирование и визуальную проверку, сообщай непроведённые проверки.
- Документация и MIT-лицензия OMR сохранены отдельно в `docs/omr/`;
  готовность исходников — в `docs/omr/TODO.md`, условия зависимостей —
  в `docs/omr/docs/dependencies.md`. Пользовательская лицензия корня сохраняется.
