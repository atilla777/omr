## Установка в отдельную рабочую область

Создана `/tmp/opencode/omr-install-check`, выполнен `git init`, без коммитов.
В ней заранее размещены пользовательские `AGENTS.md`, README, маркер лицензии,
`owner-notes.md`, команда `owner-status`, папки `demo/` и `missing/` с брифами.
Это отдельное Git-дерево вне OMR; у проектов нет вложенного `.git`.

В новом `opencode run --format json` поручено выполнить AI-блок исходного README:
прочитать SPEC/TODO и пользовательские файлы, загрузить `customize-opencode`,
подключить шесть скилов/команд, сохранить имеющиеся файлы и только дополнить
AGENTS, выполнить штатный Remotion-установщик и проверить обнаружение из `demo`.
Делегирование и вызов этапов при установке запрещены заданием проверки.

Первый процесс (`ses_ebbd36dfaffe7Vr9qfyDvA52Z9`) остановился на автоматическом отказе
`external_directory` к исходной области. Повтор запущен с ограниченным разрешением
только на исходник и временную область через `OPENCODE_CONFIG_CONTENT`:

```json
{"$schema":"https://opencode.ai/config.json","permission":{"external_directory":{"/home/aleksei/plums/omr/*":"allow","/tmp/opencode/*":"allow"}}}
```

Это настройка отдельного тестового процесса; пользовательские конфиги не менялись.
Отказ не обходился. Установка прошла в новом процессе
`ses_ebbd2f4a0ffeTetw24y2DjvIQP` после явного разрешения.
Идентификаторы и вызовы инструментов: [наблюдения](omr-workflow/observations.json).

## Ручная передача и точечные правки

Из `demo` каждый этап запускался **отдельным** поручением:

```sh
opencode run --format json --command omr-requirements '<задание этапа>'
opencode run --format json --command omr-content '<задание этапа>'
opencode run --format json --command omr-script '<задание этапа>'
opencode run --format json --command omr-render '<задание этапа>'
```

Задания: текущая папка — выбранный учебный проект; прочитать имеющиеся входы,
выполнить только данный этап, перечитать результат и остановиться, не делегировать.
Режим, тексты, дизайн, длительность и отсутствие звука даны в
[brief.md](omr-workflow/demo/brief.md). Отдельного утверждения не запрашивалось.

| Поручение | Наблюдаемое исполнение и эффект |
|---|---|
| Требования | Загрузились `omr-requirements` и RIS-метод, известные ответы не переспрашивались. Создан только `requirements.md`. |
| Контент | Прочитаны требования и бриф; реально открыты NASA Space Place и Wikipedia. Созданы только индекс и тематический материал, с F1–F3/S1–S2 и ограничениями поиска. |
| Сценарий | Прочитаны требования, индекс и материал; создан только `script.md`: два статичных экрана, [0,60) и [60,120), ссылки на F1–F3. |
| Производственная проверка входов | Все документы прочитаны, загрузились `omr-render`, `manim`, `manim-local`; выяснилось отсутствие DejaVu Sans. Файлы проекта не изменились. |
| Правка требований | Явным новым решением тестировщика шрифт заменён на доступный Noto Sans. Изменился только `requirements.md`; сценарий остался прежним. |
| Правка сценария | Отдельным `/omr-script` заменён только шрифт по текущим требованиям; остальные входы не менялись. |
| Продолжение производства | Повторно прочитаны текущие требования и сценарий; созданы код, отчёт и новый MP4, входы не переписаны. |

## Документация, лицензии и ограничения

README обновлён: фактическая готовность, ручной порядок работы, установка
из текущих исходников, сохранение пользовательских файлов, различие диагностики
и исполнения, зависимости и ограничения ресурсов. Документация зависимостей
обновлена по фактическому окружению; скилы и команды в задаче 7 не изменялись.

MIT OMR с атрибуцией проверен; upstream Remotion остаётся отдельной зависимостью
и исключён из Git, Manim-скилы не включены. Прочитана актуальная Remotion License;
она не объявляется MIT или отдельным разрешением распространять upstream-скил.
`gh repo view` подтвердил URL, PUBLIC и MIT; `origin` соответствует GitHub.
GitHub API показывает три OMR-команды и две RIS: опубликованной `omr-render`
на дату проверки ещё нет. Commit/push и публикация не поручались и не выполнялись.

Это проверка на той же машине с имеющимися глобальными Manim-скилами,
учётной записью OpenCode и установленными инструментами, не чистая ОС.
Не проверены отдельная машина, все версии OpenCode, статистический выбор скилов,
TUI/question, полное воспроизведение/прослушивание, TTS, генерация медиа сервисами,
компиляция TeX/Typst, конфликты уже изменённых одноимённых OMR-скилов при установке.
Существенные ограничения предыдущих тестов сохраняются в их отчётах.
Повторный установщик проверен, но полное повторное AI-слияние AGENTS не прогонялось.
Тестовая область оставлена локально для воспроизведения; это не установленный
проект пользователя. JSONL доступны локально в `/tmp/opencode/omr-*.jsonl`,
полные сессии — в хранилище OpenCode; в репозитории сохранены отфильтрованные
наблюдения без пользовательских конфигов и секретов.

Итоговые структурные проверки: локальные Markdown-ссылки в документации OMR
и свидетельствах (без установленных `node_modules`), метаданные четырёх скилов
и команд, Python AST, хеши сохранённых пользовательских файлов и `git diff --check`
прошли. Новые свидетельства не содержат MP4 и производственных зависимостей.
