# Проверка производства Remotion

## Результат и входы

Новый `out/video.mp4` создан в выбранном проекте
`docs/checks/omr-render/remotion`. Использованы `requirements.md`,
`content/index.md`, `script.md`; входные документы не редактировались.
Скиллы `omr-render` и `remotion-best-practices` загружены через `skill`.
Делегирования не было. Внешних медиа, речи и музыки нет.

Исходник композиции: `src/remotion/index.tsx`. Реестр ресурсов:
`public/assets.md`. Генератор звука: `renders/synthesize.py`.
Версии зависимостей зафиксированы в `package.json` и `package-lock.json`,
`node_modules` расположен внутри проекта.

## Команды

Все команды выполняются из папки проекта:

```bash
npm install --save-exact
python renders/synthesize.py
npm run bundle
npm run render
python renders/verify.py
npm ls --depth=0
```

Для чистой повторной установки использовать `npm ci` по lock-файлу.
Точная команда повторного рендера (также `npm run render`):

```bash
npx remotion render src/remotion/index.tsx TwoCards out/video.mp4 --browser-executable=/usr/bin/chromium --codec=h264 --pixel-format=yuv420p --crf=18 --audio-codec=aac --audio-bitrate=192k --audio-sample-rate=48000 --concurrency=2
```

Сборка:

```bash
npx remotion bundle src/remotion/index.tsx --out-dir=renders/bundle
```

Первая команда bundle использовала позиционный путь `renders/bundle`, который CLI
не принял как выходную папку и создал стандартный `build/`. Команда исправлена
на `--out-dir=renders/bundle`, повторная сборка успешна. Обе генерируемые папки
исключены в `.gitignore`. npm сообщил о непредоставленном разрешении postinstall
esbuild; сборка и рендер успешно отработали с установленным бинарным пакетом.

`renders/verify.py` сохраняет параметры в `renders/probe.json`, измерения в
`renders/measurements.json`, кадры в `renders/frames/` и контактный лист
`renders/contact-sheet.png`. Он запускает, в частности:

```bash
ffprobe -v error -count_frames -show_streams -show_format -of json out/video.mp4
ffmpeg -v error -i out/video.mp4 -f null -
ffmpeg -v error -y -i out/video.mp4 -vf 'select=eq(n\,59)' -frames:v 1 renders/frames/frame-059.png
ffmpeg -v error -y -i out/video.mp4 -vf 'select=eq(n\,0)+eq(n\,9)+eq(n\,59)+eq(n\,60)+eq(n\,61)+eq(n\,65)+eq(n\,69)+eq(n\,119),scale=320:180,tile=4x2' -frames:v 1 renders/contact-sheet.png
ffmpeg -v error -i out/video.mp4 -map 0:a:0 -ar 48000 -f f32le -
```

Последняя команда используется скриптом через pipe в память, без аудиоустройства.
Сигнал измеряется поканально: автоматический downmix не используется, чтобы
не исказить уровень суммированием одинаковых стереоканалов.

## Видео и просмотр реальных PNG

- Сборка, полный рендер и полное декодирование MP4 успешны.
- H.264 High, 640×360, SAR 1:1, 30/1 FPS, 120 декодированных кадров.
- Видеопоток: 4,000000 с, начало 0. Формат пикселей ffprobe: `yuvj420p`,
  полный диапазон; команда задаёт `yuv420p`.
- Фон в исходнике #101820; в декодированных PNG RGB (15,24,31),
  небольшая погрешность преобразования цвета/сжатия. Фон стабилен на стыке.
- Размер MP4: 118134 байта.

Из итогового MP4 извлечены кадры **0, 9, 59, 60, 61, 65, 69, 119**.
Открыт и визуально проверен контактный лист со всеми восемью кадрами;
дополнительно открыты полноразмерные PNG кадров 9, 65, 119 через `read`.
Это кадры финального MP4, а не самостоятельные still-рендеры.

| Кадры | Проверенное состояние |

Тексты находятся в центре, читаемы, кириллица отображается правильно;

ГОТОВО x=220…419, y=160…205. Поля 40 px соблюдены с запасом.

## Звук: измерения

Исходный `public/tone.wav`: моно PCM 16-bit, 48000 Hz, 9600 отсчётов,
ровно 0,2 с, синус 660 Hz, линейные fade-in/out по 480 отсчётов (10 ms).
Пик исходника 0,100006 FS (квантование PCM16). В композиции старт на кадре 60,
длительность 6 кадров. Других аудиоэлементов нет.

В итоговом MP4 один аудиопоток AAC-LC, 48000 Hz, stereo. Измерены реальные
декодированные отсчёты, не только наличие потока:

- Пики обоих каналов: 0,100415 FS, около −19,96 dBFS; клиппинга нет.
- Частота по положительным пересечениям нуля на 2,02–2,18 с: 660,0555 Hz.
- Активный интервал при пороге 0,001 FS (−60 dBFS):
  **2,000167–2,199854 с**, соответствует событию на склейке 2 с.
- Установившийся RMS: 0,070704 FS; RMS в первых/последних 10 ms:
  0,040057 / 0,039833 FS, согласуется с огибающей fade.
- 0–1,98 с: цифровая тишина.
- 1,98–2 с: максимум −84,81 dBFS — слабое AAC-предэхо.
- 2,2–2,22 с: максимум −61,29 dBFS — слабый AAC-хвост.
- 2,22–4 с: максимум −111,41 dBFS, практически тишина.

AAC-поток и контейнер имеют длительность **4,011 с**; декодировано
192512 отсчётов на канал, **4,010667 с**. Это пакетное дополнение AAC,
а не дополнительные видеокадры: видеоряд строго 4 с / 120 кадров.
Слабые артефакты AAC за краями эффекта отмечены отдельно от заданного
интервала исходного WAV 2–2,2 с.

## Ограничения проверки

По условию автоматического CLI-прогона **GUI, Studio и аудиоплеер не запускались**.
Интерактивного просмотра движущегося видео и прослушивания звука не было.
Визуальная проверка выполнена по реальным PNG, включая стык и промежуточные
стадии fade. Измерены частота, уровни, тишина, длительности и привязка звука
к сцене. Восприятие движения при воспроизведении и субъективное качество звука
на слух не проверены. Результат не объявляется интерактивно просмотренным
или прослушанным.
