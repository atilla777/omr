# Проверка `omr-requirements`

Дата: 16 октября 2026. OpenCode 1.18.33, агент `build`, модель
`openai/gpt-6.1-sol` (отображалась как `gpt-6.1-sol`). Проверка задачи 3 TODO;
это технический условный пример, не производство пользовательского ролика.

## Исходники и структурная проверка

- `.opencode/skills/omr-requirements/SKILL.md`: метаданные `name`, `description`,
  `license`; имя совпадает с папкой, описание задаёт положительные и соседние случаи.
  Скил самодостаточен для выбора и загрузки зависимости; локальных ресурсов нет.
- `.opencode/commands/omr-requirements.md`: только `description` во frontmatter,
  непустое тело с `$ARGUMENTS`, без фиксированной модели, агента и `subtask`.
- Метод интервью — `ris-port-op-interview`; направление зависимости одностороннее.
  Предметный владелец сохраняет документ, метод не запускает второе интервью.
- Просмотрены границы этапа, частичные входы, недоступность зависимости, повторный
  запуск, ручной переход и запрет установки движков. Машинных абсолютных путей нет.
- Из временной подпапки `.omr-requirements-check/` без собственного `.git` новый
  процесс `opencode debug config` обнаружил команду и сохранил `$ARGUMENTS`.
  `opencode debug skill` через `script -q -c ... /dev/null` обнаружил ровно один
  `omr-requirements` с непустым содержимым (6774 символа). JSON разобран Python,
  наличие шаблона и отсутствие закреплённой модели/агента/subtask проверены assert.

## Наблюдаемое выполнение команды из подпапки

Временная папка содержала только [brief.md](omr-requirements/brief.md).
Бриф задаёт все существенные решения, кроме движка, и явно разрешает свободный
порядок появления рядов/переходы. Вызов:

```sh
opencode run --format json --command omr-requirements 'Это техническая проверка на условном примере. Прочитай brief.md как предоставленные ответы. Вопросы задавай обычным текстом, по одному, чтобы ответить следующим сообщением CLI. Сохрани достаточные требования, когда неизвестное будет решено.'
```

Сессия: `ses_ebc021a79ffeFd4CJoi1W61e9B`.
Наблюдались вызовы `skill(omr-requirements)`, `skill(ris-port-op-interview)`,
чтение папки и брифа. Единственный вопрос:

> Рекомендую самостоятельный Manim: он подходит для появления геометрических
> точек рядами 1, 2, 3 и итогового равенства; сборка из внешних медиа здесь
> не требуется. Выбираем Manim?

Известные ответы повторно не спрашивались; до ответа файл не записывался.
Затем:

```sh
opencode run --session ses_ebc021a79ffeFd4CJoi1W61e9B 'Да, выбираем самостоятельный Manim.'
```

Агент записал `requirements.md` и перечитал его. Документ просмотрен независимо:
содержит тему, цель, аудиторию, исключения, стиль, 12 секунд, 1920×1080/30 FPS,
выбор Manim с основанием и источником согласия, отсутствие звука, ресурсы,
бюджет, свободу следующих этапов и оценку достаточности. Отдельного утверждения
документа не потребовалось. Контент, сценарий и производство не запускались.

## Корень области и недостаточный вход

Из корня вызвано:

```sh
opencode run --command omr-requirements 'Хочу обсудить идею короткого ролика. В этой CLI-проверке задавай вопросы обычным текстом.'
```

Агент загрузил оба скила, осмотрел область, спросил только:

> Сейчас мы в корне OMR. Какую подпапку выберем для ролика — существующую
> или новую? Укажи её имя.

Не придумал проект и тему, не записал требования в корень. В этой проверке
ответ на вопрос о подпапке не подавался; создание новой папки агентом не проверено.

## Выбор по естественному запросу и точечная правка

В новом процессе из той же тестовой подпапки, **без slash-команды**, отправлено:

> Уточни требования к этому ролику: измени только длительность на 15 секунд
> в requirements.md, сохрани остальные решения.

Агент самостоятельно загрузил `omr-requirements`, прочитал и изменил документ,
перечитал результат. Сравнение до/после: изменены ровно два упоминания 12 → 15
секунд, остальные строки сохранены. Интервью заново не начинал, метод интервью
при этой локальной правке не загружал. Итог сохранён как наблюдаемый снимок:
[requirements.md](omr-requirements/requirements.md). Бриф остаётся первоначальным
на 12 секунд; источник изменения на 15 секунд — приведённый выше запрос.

## Проверенные эффекты и ограничения

- После выполнения во временном проекте были только `brief.md` и `requirements.md`:
  нет package-файлов, `node_modules`, `.git`, исходников сцен и папок этапов.
  В наблюдаемых действиях не было команд установки или вызовов следующих этапов.
- Бриф и результат перенесены в `docs/checks/omr-requirements/` как свидетельства;
  временная рабочая папка удалена. Указание `.omr-requirements-check` в снимке —
  историческое место исполнения, а не текущий рабочий проект.
- `git diff --check` прошёл. Исходники и документация просмотрены после записи.
- Это реальные CLI-вызовы с ответом тестировщика, не интервью с владельцем
  пользовательского ролика. Вопросы шли обычным текстом; интерактивный TUI и
  инструмент `question` в этом прогоне не проверялись.
- Выбор проверен на трёх запросах, не на статистической выборке. На соседние
  будущие команды content/script/render выполнена только проверка границ текста:
  самих этих команд ещё нет.
- Генерируемая озвучка, конфликтующие документы, недоступная зависимость,
  отказ записи и все три согласуемых режима не прогонялись отдельными агентами;
  их инструкции просмотрены, но поведение не объявляется наблюдаемым.
- Движки, TTS и рендер не проверялись: они не нужны для этого этапа.
  Текущая сессия OpenCode не перечитывает каталог скилов после изменения;
  загрузка нового скила проверена новыми CLI-процессами. Для обычной работы
  следует перезапустить OpenCode.
