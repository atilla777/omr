# Технические зависимости OMR

## Официальные Remotion Agent Skills

- Источник: https://github.com/remotion-dev/skills.
- Автор/поставщик: Remotion; исходный пакет `@remotion/skills` в
  [монорепозитории](https://github.com/remotion-dev/remotion/tree/main/packages/skills).
- Зафиксированная ревизия: `1441a11e95db35443bd76bb318386c0d3ca00053`,
  версия в метаданных `4.0.536`.
- Выбран `skills/remotion-best-practices/` целиком: это самодостаточный общий
  скил с вложенными `REFERENCE.md`, примерами и ресурсами. Он охватывает создание,
  React-разметку, Studio, экспорт, субтитры, карты, медиа и справку по API.
  Отдельные верхнеуровневые скилы того же набора не нужны: они дублируют руководства.
- Локальное размещение: `.opencode/skills/remotion-best-practices/`.
  Файлы загружаются без изменений; MIT OMR на них не распространяется.

В указанной ревизии репозитория skills нет отдельного `LICENSE` и поля
`license` в `package.json`/главном `SKILL.md`. Официальный README предлагает
установку скилов. Основной проект публикует [Remotion License](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md),
а не MIT. Отдельное разрешение на перераспространение скилов под MIT не установлено.
Поэтому OMR хранит ссылку и установщик, а скачанное дерево исключено из Git.
Не добавляйте его в публикацию OMR и не приписывайте ему MIT.
При обновлении проверяйте происхождение и условия заново; имеющиеся уведомления
и атрибуцию upstream сохраняйте. Условия движка проверяются отдельно при его использовании.

Из корня исходников OMR, при наличии Python 3 и HTTPS-доступа:

```sh
python3 scripts/install-remotion-skills.py
```

Для другой существующей Git-рабочей области:

```sh
python3 scripts/install-remotion-skills.py --workspace /path/to/workspace
```

Во втором случае добавьте `/.opencode/skills/remotion-best-practices/` в
`.gitignore` целевой области. Скрипт получает архив по точному commit SHA,
не устанавливает Node-пакеты и не меняет конфигурацию OpenCode. Повторный запуск
сверяет все файлы; отличающееся дерево не перезаписывает. Обновление ревизии —
отдельное осознанное изменение установщика с повторной проверкой.

После установки перезапустите OpenCode. Загрузите `remotion-best-practices`
через `skill`, затем читайте указанные в нём руководства по необходимости.
До установки обязательная Remotion-зависимость отсутствует, даже если есть OMR.

`omr-dialogue` — локальная адаптация
[правил диалога RIS](https://github.com/atilla777/ris/blob/main/skills/ris-proj-lib-common/references/dialogue.md).

Для выбора используется доступный `question`, иначе — нумерованные текстовые
варианты. Отдельной команды у зависимости нет: она не запускает этап или интервью.

На текущей машине `manim --version` и `uv tool list` подтвердили Manim CE 0.22.0
в общем `uv tool`-окружении. Реальный рендер Pango-текста проверен в задачах 6–7.
В задаче 7 найдены `latex` и `dvisvgm` в PATH, импортирован Python-модуль `typst`,
Typst CLI не найден. Компиляция TeX/Typst не проверялась. Старое описание отсутствия
TeX в `manim-local` не заменяет проверку текущей машины. Аналогично проверяйте шрифты:
в сквозном тесте DejaVu Sans был недоступен, Noto Sans доступен.
Встроенные примеры `pip install` из общего Manim-скила не заменяют локальные
правила окружения. Не меняйте общее окружение без согласования.

## Формат команд и обнаружение

Целевая проверенная версия — OpenCode `1.18.33`. Формат четырёх команд:
`.opencode/commands/omr-<этап>.md`, YAML frontmatter с `description`, тело —
инструкция загрузить одноимённый скил через `skill` и передать `$ARGUMENTS`.
Используется текущий агент без закреплённой модели и без `subtask`.

Дополнение для единого режима: `.opencode/commands/omr.md` запускает ведущего
в текущем диалоге без закреплённой модели. Он делегирует этапы и ревью через
доступный инструмент субагентов. Отдельная `.opencode/commands/omr-review.md`
использует `agent: general`, `subtask: true`, чтобы проверку выполнял другой
исполнитель. Это исключение из формата четырёх команд этапов. При установке
переноси `omr-review/references/` целиком. Наличие инструмента и разрешений для
дочерних задач проверяется фактически; см. [проверку ведущего](checks/omr-coordinator.md).
Образец механизма — существующая `ris-port-op-interview.md`.
Имена этапов: `requirements`, `content`, `script`, `render`.
Файлы команд создаются только вместе с реализацией соответствующего скила.

Источники: [команды OpenCode](https://opencode.ai/docs/commands/),
[обнаружение скилов](https://opencode.ai/docs/skills/#understand-discovery).
Результаты исходной проверки механизма записаны в задаче 2 `TODO.md`,
полная установка и вызовы из отдельной области — в [сквозном отчёте](checks/omr-workflow.md).
`opencode debug skill` показывает доступные скилы с содержимым,
`opencode debug config` — распознанные команды с шаблонами.
Эти команды проверяют обнаружение и чтение конфигурации, но не выполнение
предметной работы агентом. Реальные вызовы четырёх команд проверены отдельно
и в последовательной передаче материалов; ограничения записаны в отчётах.

В `1.18.33` большой вывод `debug skill` при прямой передаче в pipe оказался
обрезан (неполный JSON). Для автоматической проверки на этой Linux-машине
использован псевдотерминал: `script -q -c 'opencode debug skill' /dev/null`;
перед JSON-разбором удаляются символы `\r`. Это особенность диагностического
вывода, а не отсутствие скилов. В уже запущенной до установки сессии новый скил
через `skill` не виден до перезапуска.
