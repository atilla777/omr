# OMR — Oh My Reels

Набор скилов и команд OpenCode для создания видеороликов: от обсуждения идеи
до проверенного MP4 на Remotion, Manim или их комбинации.

**Репозиторий:** https://github.com/atilla777/omr

**Состояние:** реализованы четыре этапа, два вспомогательных
RIS-скила и их команды. Добавлены ведущий `/omr` и независимый `/omr-review`;
проверки нового режима и ограничения — в [отчёте](docs/checks/omr-coordinator.md).
Проверены установка исходных четырёх этапов в отдельную Git-область с сохранением
пользовательских правил, ручная передача материалов до MP4 и точечные правки.
Производство проверено на коротких примерах трёх режимов. Отчёты и ограничения —
в [TODO.md](TODO.md) и [сквозной проверке](docs/checks/omr-workflow.md).
Репозиторий содержит результаты всех семи задач, включая `omr-render`,
примеры производства и сквозную проверку. Дальнейшие обновления публикуются
по отдельному поручению.

## Возможности

| Команда | Назначение |
|---|---|
| **`/omr`** | **Рекомендуемый старт:** от идеи до MP4 с субагентами, ревью и остановками после этапов |
| `/omr-review` | Независимая проверка выбранного этапа с отчётом в `reviews/` |
| `/omr-requirements` | Адаптивное интервью, требования и выбор движка |
| `/omr-content` | Сбор ваших материалов и внешних источников |
| `/omr-script` | Сцены, тайминг, экранные тексты, озвучка и визуальные действия |
| `/omr-render` | Исходники, медиаресурсы, проверки и готовое видео |

- Три режима: Remotion, самостоятельный Manim, вставки Manim в Remotion.
- Каждый ролик — отдельная подпапка с требованиями, контентом и сценарием
  в Markdown, исходниками и `out/video.mp4`.
- В `/omr` ведущий организует этапы и ревью; переходы — с вашего разрешения.
  Отдельные команды выполняют только свой этап, без автоматического ревью.
- Все скилы OMR подключают общий `omr-dialogue`: один вопрос за раз, выбор через
  форму OpenCode (`question`) или нумерованные варианты для ответа цифрой.
- Движки подготавливаются только при реализации: Remotion локально в проекте,
  Manim из доступного окружения либо отдельного окружения проекта при необходимости.
- Предусмотрены готовая и генерируемая озвучка, внешние и генерируемые медиа,
  техническая и визуальная проверка результата.
- Общий `omr-audio` обрабатывает готовое аудио на FFmpeg независимо от источника:
  уровни реплик, динамика речи, стыки, сведение и контроль конечного MP4.
  Генерация речи — отдельная операция; конкретный TTS не требуется для установки.

## Документы и работа отдельными сессиями

### Личные ролики в репозитории разработки

В клоне OMR храните личные ролики в `projects/<имя>/` и запускайте OpenCode
из папки выбранного ролика. Например: `projects/my-video/`. Папка `projects/`
создаётся по необходимости и целиком исключена корневым `.gitignore`, поэтому
материалы, исходники и результаты роликов не добавляются обычным `git add .`
и не входят в публикацию OMR.

Не создавайте внутри проектов собственный `.git`: родительские скилы и команды
должны оставаться доступны. Публикуемые учебные примеры и проверки находятся
отдельно в `docs/checks/` и включаются осознанно. При установке OMR в другую
рабочую область структуру проектов выбирает её владелец.

### Разработка OMR

- [SPEC.md](SPEC.md) — согласованная спецификация и границы каждого скила.
- [TODO.md](TODO.md) — последовательные задачи, критерии готовности и итоги сессий.
- [AGENTS.md](AGENTS.md) — инструкции рабочей области для трёх режимов.
- [docs/dependencies.md](docs/dependencies.md) — зависимости, происхождение,
  условия использования и формат команд OpenCode.

Для разработки в новой сессии передайте агенту:

> Прочитай AGENTS.md, SPEC.md и TODO.md. Выполни только первую незавершённую
> задачу TODO.md. При создании скила загрузи ris-port-op-author-skill через
> инструмент skill. После проверок запиши итог сессии и отметь задачу выполненной
> только при выполнении всех критериев. При блокировке запиши причину.

## Установка

Целевое размещение — `.opencode/` выбранной рабочей области. OpenCode обычно
запускается в подпапке конкретного ролика; общие скилы доступны из родительской
рабочей области в пределах одного Git-дерева.

Исходники доступны в [публичном репозитории](https://github.com/atilla777/omr).
Получить полный набор можно командой:

```sh
git clone https://github.com/atilla777/omr.git
```

Локальное подключение описано ниже. Полный новый набор содержит `omr`,
`omr-review`, четыре скила этапов, общие `omr-dialogue` и `omr-audio`, два RIS-скила и восемь
команд. Сверяйтесь
с [планом](TODO.md): опубликованная версия может отставать от рабочей копии.
Сквозная установка прежнего набора проверена отдельно; технические зависимости
подключаются по инструкции ниже.

### Зависимости и официальные инструкции

Установка скилов не устанавливает движки и системные пакеты автоматически.
Проверьте базу при подключении OMR, остальные зависимости — до соответствующей
работы. Установку отсутствующего ПО агент согласует с вами.

| Когда нужны | Зависимость | Где устанавливать / официальное руководство |
|---|---|---|
| Подключение OMR | OpenCode; прежние сквозные проверки — `1.18.33` | [OpenCode V2](https://opencode.ai/v2/docs/); версия прежней проверки не является требованием отката |
| Подключение OMR | Git, Python 3, HTTPS-доступ | [Git](https://git-scm.com/downloads), [Python](https://www.python.org/downloads/); HTTPS нужен установщику Remotion-скила |
| Проверка MP4 всех режимов; анализ и сведение звука | **FFmpeg + FFprobe в PATH** | [FFmpeg download](https://ffmpeg.org/download.html): исходники и ссылки проекта на готовые пакеты/сборки; [FFprobe](https://ffmpeg.org/ffprobe.html) |
| Remotion и гибрид | Node.js с npm; локальные React/Remotion/CLI | [Node.js](https://nodejs.org/en/download), [Remotion](https://www.remotion.dev/docs/), [установка в существующий проект](https://www.remotion.dev/docs/brownfield); точные версии и lock-файл внутри ролика |
| Remotion и гибрид | Браузер рендера и системные библиотеки | [Remotion browser ensure](https://www.remotion.dev/docs/cli/browser/ensure), [Linux dependencies](https://www.remotion.dev/docs/miscellaneous/linux-dependencies); проверять из проекта |
| Manim и гибрид | Manim Community Edition и его системные зависимости | [Установка Manim](https://docs.manim.community/en/stable/installation.html); [uv](https://docs.astral.sh/uv/getting-started/installation/) — рекомендуемый инструмент окружения, не требование всех режимов |
| Тексты | Шрифты с нужным языком и настоящими начертаниями | Например, [Noto](https://notofonts.github.io/); проверить загрузку и лицензию конкретных файлов |
| Формулы, если используются | TeX + dvisvgm **или** поддерживаемый Typst-путь Manim | [Manim text/formulas](https://docs.manim.community/en/stable/guides/using_text.html), [TeX Live](https://tug.org/texlive/), [dvisvgm](https://dvisvgm.de/), [Typst в Manim](https://docs.manim.community/en/stable/reference/manim.mobject.text.typst_mobject.html); не требовать оба стека |
| Прослушивание и просмотр | Доступный проигрыватель и реальный слушатель | Например, [mpv](https://mpv.io/installation/) или [ffplay](https://ffmpeg.org/ffplay.html); запуск проигрывателя не означает, что агент слышит звук |
| Только генерация речи / субтитры | Выбранный TTS / инструмент ASR или alignment | Универсальной зависимости нет; пример alignment — [Stable-ts](https://github.com/jianfch/stable-ts#installation). Проверить нужные модели, язык, окружение, стоимость и приватность заранее |

Скилы — тоже зависимости: `omr-audio` и `omr-dialogue` входят в OMR,
`remotion-best-practices` загружается установщиком; `manim` и `manim-local`
подключаются отдельно под фактическую машину. Источники, установка, проверки
FFmpeg, ограничения и лицензии — в [docs/dependencies.md](docs/dependencies.md).
SoX, Rubber Band, ffmpeg-normalize и конкретный TTS не обязательны.

### Порядок работы

**Начните с `/omr`.** После установки и перезапуска OpenCode запустите его
в рабочей области или папке ролика и опишите идею:

```text
/omr Хочу минутный ролик о том, почему бывают високосные годы
```

Ведущий поможет выбрать/создать подпапку, обсудит требования, объяснит различия
Remotion, Manim и гибрида и предложит рекомендацию. Технологию выбираете вы.
Контент, сценарий и производство он поручит субагентам. После каждого этапа
другой субагент проведёт ревью; предусмотрено до двух кругов исправлений после
первоначальной проверки. Затем ведущий покажет итог, пути к файлам и **спросит
разрешение продолжить**. Можно открыть файлы, обсудить изменения или остановиться.
Для контента остановка одна — после всего комплекта материалов.

Результат — `out/video.mp4`, исходники и отчёты проверок. Правки готового видео
обсуждаются в том же диалоге. Если потребуется пересмотр прежних этапов, ведущий
сначала объяснит возврат и согласует его с вами.

Для продолжения в новой сессии выберите папку ролика и вызовите `/omr` без
аргументов или с просьбой продолжить. Ведущий прочитает материалы и короткую
заметку `workflow.md` о месте остановки. Отчёты лежат в `reviews/`: есть файл —
замечания учитываются, нет файла — прежних замечаний из ревью нет. Система версий
или отдельный реестр не требуются.

### Отдельные этапы и ручная оркестрация

Можно вызывать команды по отдельности. Создайте подпапку ролика внутри рабочей
области без собственного `.git` и запустите в ней OpenCode. В клоне OMR используйте
`projects/<имя>/`; в другой области — согласованную структуру:

```text
/omr-requirements Идея ролика и известные ограничения
/omr-content
/omr-script
/omr-render
```

Эти вызовы не запускают ревью или соседние этапы. Если отчёт ревью уже есть,
исполнитель прочитает его и учтёт проблемы. Для отдельной проверки:

```text
/omr-review Проверь сценарий текущего ролика
```

При повторном вызове можно поручить конкретную правку. Изменение требований
не обновляет контент, сценарий или видео: нужную переработку следующего результата
поручите отдельно. Достаточные собственные материалы могут заменить результаты
предыдущих команд; дополнительное утверждение документов не требуется.

В текущей рабочей копии после перезапуска OpenCode можно вызвать
`/omr-requirements` из подпапки ролика или указать идею аргументом команды.
При запуске из корня команда сначала предложит выбрать подпапку. Результат —
`requirements.md`; движки не устанавливаются, следующий этап не запускается.
Подробности проверки: [интервью и выбор скила](docs/checks/omr-requirements.md).

Затем по отдельному поручению можно вызвать `/omr-content`: команда читает
требования и ваши материалы, ищет внешнюю информацию и сохраняет `content/index.md`
и тематические документы с источниками. Эквивалентный достаточный бриф допустим
вместо `requirements.md`. Ограничения доступа к источникам явно записываются;
результат остаётся базой материалов для будущего сценария.
Подробности: [проверка сбора контента](docs/checks/omr-content.md).

По отдельному поручению `/omr-script` отбирает контент и сохраняет `script.md`:
сцены, точный таймлайн, экранные тексты и озвучку, визуальные действия, ресурсы
и задание реализации в согласованном режиме. Для гибрида задаётся договор
передачи вставок Manim в Remotion. Существенные пробелы и смена режима уточняются;
движки не устанавливаются, производство не начинается.
Подробности: [проверка сценариев трёх режимов](docs/checks/omr-script.md).

По отдельному поручению `/omr-render` реализует текущий сценарий, готовит окружение
и медиа и экспортирует `out/video.mp4`. Исходники сохраняются в `src/`, команды
повторного рендера и результаты проверок — в `renders/verification.md`.
Проверяются параметры, реальные кадры, стыки и предусмотренный звук. Поиск ресурсов
зависит от доступных сайтов/инструментов; проверены API-каталог NASA, скачивание
изображения и локальный синтез короткого тона. TTS и генерация изображений/видео
через внешние сервисы не проверены и требуют реального инструмента и доступа.
В автоматических примерах звук измерен без прослушивания, видео проверено по PNG.
Подробности: [производство в трёх режимах](docs/checks/omr-render.md).

### Инструкция для агента: установка OMR в папку проекта

Пользователь может передать агенту следующий запрос вместе с этим README:

> Установи пакет скилов OMR из https://github.com/atilla777/omr в текущую папку
> проекта по инструкции ниже. Если нужные файлы ещё не опубликованы, используй
> предоставленную актуальную локальную копию, не создавай команды-пустышки.
> Сохрани существующие инструкции, команды и скилы, сравни одноимённые файлы.
> Подключи `/omr` как рекомендуемый способ работы, отдельные этапы и `/omr-review`.
> Не устанавливай движки и не начинай создавать ролик. Проверь обнаружение
> компонентов, доступность FFmpeg/FFprobe и применимые зависимости по таблице выше.
> Сообщи недостающее ПО с официальными ссылками установки и необходимость перезапуска.

Под папкой проекта здесь понимается рабочая область, куда устанавливается
`.opencode/`; отдельные ролики создаются внутри неё. Не создавай дополнительный
клон OMR с собственным `.git` внутри папки ролика.

Установка прежнего набора четырёх этапов проверена на OpenCode `1.18.33`:
[свидетельства](docs/checks/omr-workflow.md). Проверки новых компонентов и блокер
делегирования описаны [отдельно](docs/checks/omr-coordinator.md).

1. Прочитайте `SPEC.md`, особенно разделы [о рабочей области](SPEC.md#workspace),
   [зависимостях](SPEC.md#dependencies) и [установке](SPEC.md#installation).
   Проверьте фактическую готовность исходников по `TODO.md` и наличие файлов
   ведущего, ревью и четырёх этапов: опубликованная версия может отставать от рабочей копии.
2. Определите целевую рабочую область и прочитайте её существующий `AGENTS.md`.
   При работе с OpenCode загрузите доступный профильный скил `opencode` и используйте
   документацию V2. Не требуйте отсутствующий устаревший `customize-opencode`.
   Согласуйте место установки; при внешнем исходном каталоге нужен доступ к нему.
   Не обходите отказ доступа: запросите разрешение или доступную копию.
3. Рабочая область должна быть Git-деревом. При использовании клона OMR локальные
   файлы уже размещены в нужных местах. Для существующей области перенесите из
   проверенных исходников OMR каталоги скилов из `.opencode/skills/` и Markdown-команды
   из `.opencode/commands/` в одноимённые папки области. Переносите только реально
   реализованные компоненты по `TODO.md`; сейчас это два RIS-скила,
   `omr`, `omr-review`, `omr-dialogue`, `omr-audio`, `omr-requirements`, `omr-content`,
   `omr-script`, `omr-render` и восемь команд (у `omr-dialogue` и `omr-audio`
   отдельных команд нет). Переносите папки скилов целиком: каталоги `references/`
   у `omr-review` и `omr-audio` обязательны, одного `SKILL.md` недостаточно.
   Сохраните `LICENSE`, документацию, `scripts/install-remotion-skills.py` и атрибуцию.
   Сравнивайте одноимённые файлы до переноса, сохраняйте пользовательские изменения.
   Не заменяйте пользовательские `README.md` и `LICENSE` документацией OMR.
   Например, сохраните комплект `README.md`, `SPEC.md`, `TODO.md`, `AGENTS.md`,
   `LICENSE` и `docs/` OMR под `docs/omr/`, сохранив относительную структуру;
   укажите происхождение и расположение в правилах области. Существующий установщик
   также сравните перед переносом. Копируйте предназначенные для распространения
   материалы, без локальных MP4, кэшей и зависимостей тестовых проектов.
   Не переносите `.opencode/node_modules`, её служебные package-файлы, `.git`
   источника или глобальные настройки. Вложенный Git-репозиторий для ролика не нужен.
4. Из исходников OMR выполните `python3 scripts/install-remotion-skills.py`
   (для другой области добавьте `--workspace /path/to/workspace`). Это загружает
   официальный `remotion-best-practices` по фиксированной ревизии, включая ресурсы;
   движок Remotion не устанавливается. Добавьте в `.gitignore` области
   `/.opencode/skills/remotion-best-practices/`. Подробности и условия —
   в [зависимостях](docs/dependencies.md). Для Manim проверьте наличие `manim` и
   `manim-local`; при отсутствии согласуйте подключение. Эти пользовательские скилы
   не входят в репозиторий OMR. Не копируйте персональные пути с другой машины.
   Проверьте зависимости по таблице выше и чек-листу `docs/dependencies.md`:
   в частности, `ffmpeg -version`, `ffprobe -version`, нужные фильтры и кодеки.
   Встроенный FFmpeg Remotion не заменяет доступность этих CLI. Не устанавливайте
   системные пакеты/движки без согласования; не переносите локальные инструкции
   и настройки TTS, эталоны голосов или персональные пути как зависимости OMR.
5. Дополните `AGENTS.md`, сохранив имеющиеся инструкции, следующими правилами:
   - каждый ролик находится в отдельной подпапке рабочей области;
   - требования, контент и сценарий хранятся по структуре OMR;
   - поддерживаются Remotion, Manim и гибрид; режим согласуется в требованиях;
   - профильные скилы загружаются перед соответствующей работой;
   - для предусмотренного звука производство и ревью загружают `omr-audio`;
     обработка готовых файлов на FFmpeg не зависит от способа генерации речи;
     исходники сохраняются, конечный звук измеряется и проверяется на слух;
   - все скилы OMR загружают `omr-dialogue` через `skill` в своём контексте;
     выбор — через `question` либо нумерованные текстовые варианты, один вопрос за раз;
   - движки не устанавливаются заранее; зависимости принадлежат проекту
     либо используются из подходящего имеющегося окружения Manim;
   - `/omr` — рекомендуемый вход: требования ведёт основной агент, остальные
     этапы — субагенты; после каждого этапа отдельный субагент выполняет ревью,
     затем ведущий показывает результат и ждёт разрешения продолжить;
   - после первоначального ревью — до двух кругов исправлений с повторной проверкой;
   - отдельные команды этапов не запускают ревью и другие этапы;
   - существующие `reviews/<этап>.md` учитываются исполнителями; версии и реестр
     не нужны; `workflow.md` хранит короткую заметку для возобновления;
   - недостаточные входы уточняются, возврат к предыдущим этапам согласуется.
6. Откройте новую сессию OpenCode после подключения. В подпапке ролика без
   собственного `.git` проверьте обнаружение и загрузку через `skill`:
   должны быть доступны родительские RIS-скилы, `remotion-best-practices`,
   `omr`, `omr-review`, `omr-dialogue`, `omr-audio`, `omr-requirements`, `omr-content`,
   `omr-script`, `omr-render` и восемь команд (две RIS, четыре этапа, ведущий и ревью)
   с непустыми шаблонами в интерфейсе установленной версии. Для каждого применимого
   режима проверьте именно загрузку технических скилов, не только наличие каталогов.
   Для `/omr` нужен доступный инструмент делегирования субагентам с правом записи.
   Старые `opencode debug skill` / `debug config` проверялись на `1.18.33`;
   в проверенной V2 `2.0.32` подкоманды `debug skill` нет, а `debug config`
   показывает источники конфигурации. Не используйте их как универсальный
   тест всех скилов/команд. Сверяйтесь со справкой и документацией V2,
   не требуйте отката версии.
   В новой сессии загрузите зависимости через `skill`;
   для Manim — оба скила вместе. Команды OMR используют Markdown-файлы
   `.opencode/commands/omr.md` и `omr-*.md` с `description` и телом с `$ARGUMENTS`;
   у отдельного ревью также заданы `agent: general` и `subtask: true`;
   обнаружение само по себе не подтверждает предметное выполнение.
   По отдельному поручению проверьте команды на маленьком учебном примере,
   вызывая этапы вручную; MP4 проверяйте по реальным кадрам, параметрам и звуку.
   Сообщите изменённые файлы, результаты проверок и недоступные зависимости.
